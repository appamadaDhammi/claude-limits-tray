# Claude Limits

Плавающая панель для macOS: расход лимитов Claude и состояние сервисов — на рабочем столе,
без открывания Claude Code.

```
┌────────────────────────────┐
│  ✳ Claude Limits    MAX    │
│  Сессия · 5ч          13%  │
│  ▓▓░░░░░░░░░░  до 04:30    │
│  Неделя · всё          3%  │
│  ▓░░░░░░░░░░░  до ср 01:00 │
│  Неделя · Fable        2%  │
│  ▓░░░░░░░░░░░  до ср 01:00 │
│  ───────────────────────── │
│  ● Claude Code  работает ⌄ │
│  обновлено 2 мин назад     │
└────────────────────────────┘
```

## Что показывает

- **Три лимита** — часовой (5 ч), недельный общий и недельный по Fable — в процентах
  израсходованного, с временем обнуления по местному времени.
- **Состояние сервисов Claude** — свёрнутой строкой; клик раскрывает список активных инцидентов
  и неисправных компонентов.

Цвет процента меняется на 80% и 95%; при тех же порогах приходят системные уведомления.

## Требования

macOS 13+, установленный и залогиненный **Claude Code**. Утилита читает его OAuth-токен из
Keychain — своего входа у неё нет и быть не может: клиент Claude Code не принимает авторизацию
извне, а `claude setup-token` выпускает токен без нужного разрешения (подробности и проверки —
в [дизайне](docs/superpowers/specs/2026-08-26-claude-limits-tray-design.md), раздел 2.3).

## Установка

```bash
curl -fsSL https://kadu.su/claudelimits/install.sh | bash
```

Или скачать файлом со страницы [kadu.su/claudelimits](https://kadu.su/claudelimits/) — там же
DMG, PKG и ZIP.

**Про предупреждение macOS.** Приложение подписано ad-hoc, а не сертификатом Apple Developer
(он платный, для личной утилиты его нет). На всё скачанное браузером система ставит карантинную
метку и отказывается открывать: «повреждено» или «неизвестный разработчик». Обходится один раз —
правый клик по программе, «Открыть», затем «Открыть» в диалоге. Команда выше снимает метку сама,
поэтому предупреждения не будет.

## Сборка

Xcode не нужен, достаточно Command Line Tools.

```bash
./make.sh              # тесты + сборка в build/Claude Limits.app
./make.sh --install    # то же + установка в /Applications и запуск
./package.sh           # то же + dmg/pkg/zip/install.sh и страница в dist/
```

При первом запуске macOS спросит доступ к связке ключей — нажмите **«Всегда разрешать»**.
Каждая пересборка меняет ad-hoc подпись, поэтому во время разработки вопрос повторяется.

## Управление

Панель таскается за любое место, положение запоминается. На её поверхности нет кнопок —
всё по правой кнопке мыши:

- **Обновить сейчас** — внеочередной запрос лимитов и состояния
- **Запускать при входе** — автозапуск через `SMAppService`
- **Закрыть Claude Limits**

Окно принадлежит одному рабочему столу, поэтому его можно перетаскивать между столами в Mission
Control. Показать его сразу на всех столах нельзя — это взаимоисключающие режимы macOS.

## Как это устроено

Данные о лимитах — `GET api.anthropic.com/api/oauth/usage`, тот же эндпоинт, что у панели
`/usage` в Claude Code. Состояние сервисов — `status.claude.com/api/v2/summary.json`, без
авторизации. Опрос раз в 5 минут: эндпоинт лимитов жёстко ограничивает частоту, и квота общая с
самим Claude Code, поэтому `429` здесь нормальное явление и ошибкой не считается.

Токен читается из Keychain **только на чтение**, держится в памяти до истечения срока и никуда
не записывается. Сторонних зависимостей нет; наружу приложение ходит ровно по двум адресам.

Если что-то не так, причина пишется в панели своими словами и подробнее — в журнале
`~/Library/Logs/ClaudeLimits.log` (токен туда не попадает, файл обрезается до 200 строк).

## Тесты

```bash
swift run LimitsTests
```

58 проверок: разбор ответов обоих эндпоинтов, чтение записи Keychain, пороги уведомлений,
форматирование времени и именование отказов. XCTest недоступен без полного Xcode, поэтому тесты
собраны отдельным исполняемым таргетом.
