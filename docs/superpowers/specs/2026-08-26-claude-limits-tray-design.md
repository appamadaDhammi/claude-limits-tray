# Claude Limits — трей-утилита для macOS (дизайн)

**Дата:** 2026-08-26 · **Статус:** DRAFT на вычитку · **Проверки:** все утверждения раздела 2
получены живыми пробами вечером 2026-08-25/26; пробники были одноразовыми и в репозиторий не
входят — воспроизводящие команды приведены при каждом факте.

## 1. Цель и границы

Утилита в строке меню macOS, показывающая расход лимитов Claude: часовой (5 ч), недельный общий и
недельный по модели Fable — с временем обнуления каждого. Смысл — видеть расход не открывая
Claude Code и не набирая `/usage`.

В границах: чтение токена Claude Code из Keychain, один HTTP-запрос за цифрами, отрисовка в трее
и выпадающей панели, уведомления по порогам, автозапуск при входе в систему.

Вне границ: extra usage / кредиты (пользователь отказался явно), история расхода и графики,
любая запись в Keychain, любой собственный вход в аккаунт (раздел 2.3 объясняет почему),
поддержка Linux и Windows.

## 2. Что установлено проверками

Этот раздел — капитал вечера. Каждое утверждение проверено, а не выведено из документации.

### 2.1 Источник данных

`GET https://api.anthropic.com/api/oauth/usage` с заголовком `Authorization: Bearer <токен>`
возвращает `200` и массив `limits[]`, где лежит ровно то, что нужно:

| Что показываем | Строка ответа | Поля |
|---|---|---|
| Часовой лимит | `kind == "session"` | `percent`, `resets_at` |
| Недельный общий | `kind == "weekly_all"` | `percent`, `resets_at` |
| Недельный Fable | `kind == "weekly_scoped"` и `scope.model.display_name == "Fable"` | `percent`, `resets_at` |

Установленные свойства:

- **`percent` — это использованное, а не остаток.** За час наблюдения часовой вырос 9% → 13%,
  недельный 2% → 3% по мере работы.
- **Тот же ответ содержит легаси-поля** `five_hour.utilization` и `seven_day.utilization`,
  совпадающие с соответствующими строками `limits[]` (13.0 против 13). Это внутренняя сверка, но
  **брать надо `limits[]`**: у Fable легаси-поле `seven_day_overage_included` равно `null`, хотя в
  коде Claude Code подписано как «Fable 5 limit». Читатель легаси-полей получил бы вечно пустую
  строку Fable.
- **Запрос не тратит квоту** — это чтение счётчика, а не обращение к модели.
- **Достаточно одного заголовка `Authorization`**; `anthropic-beta` и `anthropic-version` не нужны
  (проверено: тот же `200` без них).
- **`resets_at` — ISO 8601 в UTC**, переводится в локальную зону на отрисовке.
- Это тот же эндпоинт, которым пользуется сам Claude Code: в его бинаре присутствует
  `fetchUtilization: GET /api/oauth/usage`, а подпись «Current week (Fable)» строится из
  `weekly_scoped` → `scope.model.display_name`.

Проверка: `curl -s -o /dev/null -w '%{http_code}' https://api.anthropic.com/api/oauth/usage -H "Authorization: Bearer $TOKEN"` → `200`.

### 2.2 Носитель доступа

Эндпоинт требует scope **`user:profile`** — это не догадка, сервер называет его прямым текстом:
`403 permission_error: "OAuth token does not meet scope requirement user:profile"`.

Единственный доступный носитель этого scope — токен Claude Code в macOS Keychain:

- сервис `Claude Code-credentials`, аккаунт — имя пользователя;
- значение — JSON, внутри объект `claudeAiOauth` с полями `accessToken`, `refreshToken`,
  `expiresAt`, `refreshTokenExpiresAt`, `scopes`, `subscriptionType`, `rateLimitTier`;
- срок жизни access-токена — около 8 часов; Claude Code обновляет его сам при работе.

Проверка: `security find-generic-password -s "Claude Code-credentials" -w`.

### 2.3 Почему нет собственного входа

Проверено и отвергнуто, чтобы к этому не возвращались:

1. **Свой OAuth PKCE-вход** с client_id Claude Code — четыре попытки, все отклонены сервером после
   экрана согласия («Invalid request format»): loopback на динамическом порту, loopback на родном
   для CC порту 54545, ручной редирект `platform.claude.com/oauth/code/callback`, минимальный и
   полный набор scope. Клиент Claude Code не принимает авторизацию извне своего приложения.
2. **`claude setup-token`** — токен выпускается валидный, но **без `user:profile`**: он
   предназначен для inference по подписке (CI, обёртки), а не для чтения данных аккаунта. На
   эндпоинте лимитов даёт `403`, на Messages API работает.
3. **Общая практика подтверждает то же.** Все существующие менюбарки того же назначения читают
   токен Claude Code из Keychain только на чтение; своего входа не делает никто:
   [claude-limits](https://github.com/kacharhin/claude-limits),
   [claude-codex-limits](https://github.com/ArrivaRUS/claude-codex-limits),
   [token-usage](https://github.com/JBotwina/token-usage),
   [ClaudeBar](https://gordonbeeming.com/projects/claude-bar),
   [cclimit](https://cclimit.app/).

Следствие для продукта: утилита работает при установленном и залогиненном Claude Code. Для
целевого сценария это не ограничение.

### 2.4 Урок чужой аварии

В трекере CodexBar ([issue #1844](https://github.com/steipete/CodexBar/issues/1844)) описан отказ: на части установок Claude Code 2.1.x в
`Claude Code-credentials` лежат только записи `mcpOAuth`, без основного токена. Приложение не
смогло разобрать значение, сочло токен протухшим и начало «делегированное обновление» — вызывая
`/usr/bin/open` каждые несколько минут и воскрешая браузер пользователя. В issue это названо
поведением, неотличимым от зловреда.

Отсюда нормативное правило этого дизайна, раздел 6: **утилита не запускает ничего сама** и не
пытается чинить авторизацию.

### 2.5 Инструментарий машины

- Swift 5.10, только Command Line Tools (полного Xcode нет). SwiftUI и `MenuBarExtra`
  компилируются — проверено `swiftc -parse`. `ServiceManagement`, `UserNotifications`, `Security`
  доступны.
- **XCTest недоступен**: `swift test` падает с `error: XCTest not available` (нужен полный Xcode).
  Отсюда решение по тестам в разделе 10.

## 3. Что видно пользователю

### 3.1 Строка меню

Часовой лимит в процентах использованного: `✳ 13%`. Моноширинные цифры — строка не дёргается при
смене значения. Цвет: обычный текст до 80%, коралловый акцент Claude (#D97757) с 80%, красный с
95%.

### 3.2 Панель по клику

```
  ✳  Claude Limits                 Max 20x
 ────────────────────────────────────────
  Сессия · 5ч        ▓▓░░░░░░░░░░    13%
                     обнулится в 04:30
  Неделя · всё       ▓░░░░░░░░░░░     3%
                     обнулится в ср 01:00
  Неделя · Fable     ▓░░░░░░░░░░░     2%
                     обнулится в ср 01:00
 ────────────────────────────────────────
  обновлено 02:14 · ⟳ Обновить
  Настройки…                    Выход
```

Время сброса — локальное. Строка Fable скрывается, если её нет в ответе (у аккаунтов без
Fable-лимита). Тариф в шапке — из `subscriptionType` в Keychain.

### 3.3 Настройки

Ровно три переключателя, больше не нужно:

- **Уведомления** — вкл/выкл (по умолчанию вкл);
- **Запускать при входе в систему** — вкл/выкл (по умолчанию выкл, включается осознанно);
- **Показывать недельные лимиты** — вкл/выкл (по умолчанию вкл; кому хватает часового).

Хранятся в `UserDefaults` — это настройки, не секреты. Интервал опроса не настраивается: 60 секунд
подобраны под бесплатный эндпоинт и менять их незачем.

## 4. Архитектура

Пять файлов, каждый с одной ответственностью:

| Файл | Делает | Зависит от |
|---|---|---|
| `Credentials.swift` | читает keychain-item, разбирает `claudeAiOauth`, отдаёт токен или типизированную ошибку | Security.framework |
| `UsageClient.swift` | один GET, разбор ответа в `Limits` | URLSession |
| `LimitsStore.swift` | таймер, состояние, пороги уведомлений; единственный источник правды для UI | первые два |
| `MenuView.swift` | панель SwiftUI | store |
| `App.swift` | `MenuBarExtra`, заголовок строки меню, автозапуск | store |

Первые три не знают про UI и покрываются тестами. `Credentials.swift` **не имеет функций записи**
— отсутствие такой возможности является гарантией, а не обещанием.

## 5. Модель данных

```swift
struct Limit { let percent: Int; let resetsAt: Date? }
struct Limits { let session: Limit?; let weeklyAll: Limit?; let weeklyFable: Limit? }
```

Разбор: идём по `limits[]`, отбираем по `kind`; для `weekly_scoped` дополнительно сверяем
`scope.model.display_name == "Fable"`. Неизвестные `kind` игнорируются молча — ответ содержит и
другие строки, их состав может меняться. Отсутствующая строка даёт `nil`, а не ноль: «нет данных»
и «ноль процентов» — разные вещи и рисуются по-разному.

## 6. Состояния и поведение при отказах

| Состояние | Причина | Трей | Панель |
|---|---|---|---|
| `ok` | ответ получен | `✳ 13%` | три лимита |
| `stale` | сеть недоступна | последнее значение серым | «обновлено 12 мин назад» |
| `expired` | `401` от эндпоинта | `✳ —` | «Запусти Claude Code — он обновит токен» |
| `noCredentials` | нет `claudeAiOauth` или доступ к Keychain не дан | `✳ —` | «Нет доступа к токену Claude Code» |

Правила, обязательные к соблюдению:

1. **Утилита не запускает внешние программы** — ни браузер, ни `claude`, ни `open`. Ни при каких
   состояниях. (Раздел 2.4.)
2. **Не пытается обновить токен** в первой версии. Обновление — операция с ротацией refresh-токена;
   единственный способ сломать пользователю рабочий вход в Claude Code. Отложено в раздел 11.
3. **Отступ при отказах**: обычный интервал 60 с; после ошибки — 5 минут; `429` без токена
   трактуется как проблема авторизации, а не как частота (проверено: запрос без токена даёт `429`,
   а не `401`).
4. **Последнее удачное значение не стирается** ошибкой — показывается серым с отметкой давности.

Опрос: каждые 60 секунд, при открытии панели, при пробуждении из сна.

## 7. Уведомления

Пороги 80% и 95% по любому из трёх лимитов, по одному разу на окно (запоминается сработавший порог
и `resets_at`; при смене окна счётчик сбрасывается). Отдельно — «часовой лимит обнулился» при
переходе окна. Всё отключаемо в настройках; при выключенных уведомлениях разрешение у системы не
запрашивается вовсе.

## 8. Безопасность

- Токен **никогда** не покидает память процесса: ни файла, ни `UserDefaults`, ни лога. В отладочный
  вывод при необходимости идёт длина или sha256-префикс, но не значение.
- **Ноль сторонних зависимостей** — только системные фреймворки. Цепочки поставок, через которую
  что-то может утечь, не существует.
- Сеть: единственный адрес `api.anthropic.com` по TLS. Ни телеметрии, ни аналитики, ни отчётов о
  сбоях наружу.
- App Sandbox с правами только на исходящую сеть и Keychain; доступа к файловой системе у
  приложения нет.
- Работа с Keychain — **только чтение**. Подпись ad-hoc локально.
- Ответ эндпоинта не кэшируется на диск.

## 9. Сборка и установка

SwiftPM собирает исполняемый файл; скрипт `make.sh` укладывает его в `Claude Limits.app` с
`Info.plist` (`LSUIElement = true` — без иконки в доке) и подписывает ad-hoc. Xcode не требуется.
Автозапуск — `SMAppService.mainApp.register()` по галочке в настройках.

## 10. Тесты

XCTest недоступен (раздел 2.5), поэтому тесты — отдельный исполняемый таргет `LimitsTests`,
запускаемый `swift run LimitsTests`, с ненулевым кодом возврата при провале. Под тестами:

- разбор JSON-фикстур: полный ответ, ответ без строки Fable, ответ с неизвестными `kind`,
  ответ с `resets_at: null`;
- выбор строки Fable именно по `display_name`, а не по позиции;
- логика порогов: срабатывание один раз на окно, сброс при смене `resets_at`;
- перевод `resets_at` в локальное время и форматирование «через N ч M мин»;
- состояния: `401` → `expired`, сетевой отказ → `stale` с сохранением прежних значений,
  отсутствие `claudeAiOauth` → `noCredentials`.

Фикстуры — реальные ответы эндпоинта с вычищенными идентификаторами. UI тестами не покрывается.

## 11. Вне границ, с адресами

1. **Обновление токена своими силами** (refresh + запись обратно в keychain-item в формате Claude
   Code) — снимает засыпание трея после 8 часов без Claude Code. Триггер: если на практике
   окажется, что трей слепнет заметно часто. Требует отдельной проверки на риск рассинхрона с CC.
2. **Extra usage / кредиты** — данные уже приходят в том же ответе (`spend`, `extra_usage`).
   Триггер: если пользователь начнёт ими пользоваться.
3. **История расхода** — накопление замеров и график в панели. Триггер: появится вопрос «когда
   я обычно упираюсь».
4. **Поддержка иного размещения токена** — если Claude Code сменит формат хранения (раздел 2.4
   показывает, что такое случается). Триггер: первая же поломка чтения.

## 12. Риски

| Риск | Вероятность | Что делаем |
|---|---|---|
| Claude Code меняет формат хранения токена | средняя (прецедент в 2.1.x) | типизированная ошибка и честное состояние `noCredentials`, без попыток чинить |
| Эндпоинт меняет форму ответа | низкая | неизвестные `kind` игнорируются; отсутствующая строка даёт `nil`, а не падение |
| Пользователь не дал доступ к Keychain | высокая при первом запуске | состояние `noCredentials` с текстом про «Всегда разрешать»; повторный запрос — по клику, не автоматически |
| Fable-лимит отсутствует у аккаунта | известная | строка просто не рисуется |
