# Claude Limits — плавающая панель для macOS (дизайн)

**Дата:** 2026-08-26, обновлено 2026-08-28 по итогам работы вживую · **Статус:** реализовано,
описывает текущее поведение · **Проверки:** все утверждения раздела 2 получены живыми пробами;
воспроизводящие команды приведены при каждом факте.

## 1. Цель и границы

Панель на рабочем столе, показывающая расход лимитов Claude: часовой (5 ч), недельный общий и
недельный по модели Fable — с временем обнуления каждого. Плюс состояние сервисов Claude с
раскрывающимся списком инцидентов. Смысл — видеть и то, и другое не открывая Claude Code и не
набирая `/usage`.

В границах: чтение токена Claude Code из Keychain, запрос лимитов, запрос публичной страницы
состояния, отрисовка в плавающем окне, уведомления по порогам, автозапуск при входе, журнал
отказов.

Вне границ: extra usage / кредиты (пользователь отказался явно), история расхода и графики,
любая запись в Keychain, любой собственный вход в аккаунт (раздел 2.3 объясняет почему),
поддержка Linux и Windows.

## 2. Что установлено проверками

Этот раздел — капитал: каждое утверждение проверено, а не выведено из документации.

### 2.1 Источник данных о лимитах

`GET https://api.anthropic.com/api/oauth/usage` с заголовком `Authorization: Bearer <токен>`
возвращает `200` и массив `limits[]`:

| Что показываем | Строка ответа | Поля |
|---|---|---|
| Часовой лимит | `kind == "session"` | `percent`, `resets_at` |
| Недельный общий | `kind == "weekly_all"` | `percent`, `resets_at` |
| Недельный Fable | `kind == "weekly_scoped"` и `scope.model.display_name == "Fable"` | `percent`, `resets_at` |

Установленные свойства:

- **`percent` — это израсходованное, а не остаток.** За час наблюдения часовой вырос 9% → 13%.
- **Брать надо `limits[]`, а не легаси-поля.** В том же ответе есть `five_hour.utilization` и
  `seven_day.utilization`, совпадающие с соответствующими строками; но у Fable легаси-поле
  `seven_day_overage_included` равно `null`, хотя в коде Claude Code подписано как «Fable 5
  limit». Читатель легаси-полей получил бы вечно пустую строку Fable.
- **Запрос не тратит квоту модели** — это чтение счётчика.
- **Достаточно одного заголовка `Authorization`**; `anthropic-beta` и `anthropic-version` не
  нужны (проверено: тот же `200` без них).
- **`resets_at` — ISO 8601 в UTC**, переводится в локальную зону на отрисовке.

Проверка: `curl -s -o /dev/null -w '%{http_code}' https://api.anthropic.com/api/oauth/usage -H "Authorization: Bearer $TOKEN"` → `200`.

### 2.2 Жёсткое ограничение частоты (найдено вживую 2026-08-27)

**Эндпоинт пускает примерно один запрос в две минуты, а квота общая с самим Claude Code** — он
ходит на тот же адрес за своим `/usage`. Превышение даёт `429`, причём заголовок `Retry-After`
приходит нулевым и паузы не сообщает.

Проверка (два запроса подряд): первый → `200`, второй через 3 секунды → `429 retry-after: 0`.

Следствия, заложенные в поведение (раздел 6):

- Опрос раз в **5 минут**, а не в минуту. Расход меняется медленно; частый опрос лишь отбирает
  запросы у Claude Code и получает отказы.
- **`429` — не ошибка.** Он значит «только что спрашивал кто-то другой», а показанные цифры
  при этом остаются верными. Панель не меняет ни состояния, ни отметки времени, а просто
  переносит следующий опрос.

Как это выглядело до фикса: журнал показывал `HTTP 429` каждые две минуты, панель писала «нет
сети» при живом интернете, а кнопка «Обновить сейчас» била в ту же стену.

### 2.3 Носитель доступа и почему нет собственного входа

Эндпоинт требует scope **`user:profile`** — сервер называет его прямым текстом:
`403 permission_error: "OAuth token does not meet scope requirement user:profile"`.

Единственный доступный носитель — токен Claude Code в macOS Keychain: сервис
`Claude Code-credentials`, значение — JSON с объектом `claudeAiOauth` (`accessToken`,
`refreshToken`, `expiresAt` в миллисекундах, `subscriptionType`). Срок жизни access-токена
около 8 часов; Claude Code обновляет его сам.

Проверка: `security find-generic-password -s "Claude Code-credentials" -w`.

Проверено и отвергнуто, чтобы к этому не возвращались:

1. **Свой OAuth PKCE-вход** с client_id Claude Code — четыре попытки, все отклонены сервером
   после экрана согласия («Invalid request format»): loopback на динамическом порту, loopback на
   родном для CC порту 54545, ручной редирект `platform.claude.com/oauth/code/callback`,
   минимальный и полный набор scope. Клиент Claude Code не принимает авторизацию извне своего
   приложения.
2. **`claude setup-token`** — токен выпускается валидный, но **без `user:profile`**: он
   предназначен для inference по подписке (CI, обёртки), а не для чтения данных аккаунта. На
   эндпоинте лимитов даёт `403`.
3. **Общая практика та же.** Все существующие менюбарки того же назначения читают токен Claude
   Code из Keychain только на чтение; своего входа не делает никто:
   [claude-limits](https://github.com/kacharhin/claude-limits),
   [claude-codex-limits](https://github.com/ArrivaRUS/claude-codex-limits),
   [token-usage](https://github.com/JBotwina/token-usage),
   [ClaudeBar](https://gordonbeeming.com/projects/claude-bar),
   [cclimit](https://cclimit.app/).

Следствие: утилита работает при установленном и залогиненном Claude Code. Для целевого сценария
это не ограничение.

### 2.4 Источник данных о состоянии сервисов

`GET https://status.claude.com/api/v2/summary.json` (без авторизации) отдаёт всё нужное одним
ответом: общий индикатор (`none`/`minor`/`major`/`critical`), компоненты и активные инциденты.
Среди компонентов **Claude Code — отдельная строка**; рядом `Claude API (api.anthropic.com)`,
`claude.ai`, `Claude Console`. Записи с `group: true` — заголовки разделов, а не сервисы.

Проверка: `curl -sL https://status.claude.com/api/v2/summary.json | python3 -m json.tool`.

Токен на этот адрес не отправляется никогда.

### 2.5 Урок чужой аварии

В трекере CodexBar ([issue #1844](https://github.com/steipete/CodexBar/issues/1844)) описан
отказ: на части установок Claude Code 2.1.x в `Claude Code-credentials` лежат только записи
`mcpOAuth`, без основного токена. Приложение не смогло разобрать значение, сочло токен протухшим
и начало «делегированное обновление» — вызывая `/usr/bin/open` каждые несколько минут и воскрешая
браузер пользователя. В issue это названо поведением, неотличимым от зловреда.

Отсюда нормативное правило раздела 6: **утилита не запускает ничего сама** и не пытается чинить
авторизацию.

### 2.6 Инструментарий машины

- Swift 5.10, только Command Line Tools (полного Xcode нет). SwiftUI, `ServiceManagement`,
  `UserNotifications`, `Security` доступны.
- **XCTest недоступен**: `swift test` падает с `error: XCTest not available`. Отсюда решение по
  тестам в разделе 10.

## 3. Что видно пользователю

### 3.1 Плавающая панель

Небольшое окно на рабочем столе, поверх обычных окон. Таскается за любое место, положение
запоминается и переживает перезапуск; если сохранённая точка оказалась вне текущих экранов
(отключили монитор) — панель возвращается в правый верхний угол.

```
┌────────────────────────────┐
│  ✳ Claude Limits    MAX    │
│  Сессия · 5ч          13%  │
│  ▓▓░░░░░░░░░░  до 04:30    │
│  Неделя · всё          3%  │
│  ▓░░░░░░░░░░░  до ср 01:00 │
│  Неделя · Fable        2%  │
│  ▓░░░░░░░░░░░  до ср 01:00 │
│  ─────────────────────────  │
│  ● Claude Code  работает ⌄ │
│  обновлено 2 мин назад     │
└────────────────────────────┘
```

Цвет процента: обычный текст до 80%, коралловый акцент Claude (#D97757) с 80%, красный с 95%.
Строка Fable скрывается, если её нет в ответе. Тариф в шапке — из `subscriptionType`.

**Строка возраста данных живёт своим временем.** Она обёрнута в `TimelineView` с шагом 30 с:
обычный текст пересчитывается только при изменении данных, то есть в момент удачного запроса, и
потому вечно показывал бы «обновлено только что», сколько бы времени ни прошло (эта ошибка была
допущена и исправлена 2026-08-27).

### 3.2 Блок состояния сервисов

Свёрнутая строка: цветная точка + «Claude Code» + состояние. Клик раскрывает окно, где
показываются активные инциденты (название, стадия, время и последнее сообщение) и все
неработающие компоненты. Исправные компоненты в списке не перечисляются — шесть зелёных строк
не сообщают ничего; при полном благополучии пишется «Все сервисы работают, инцидентов нет».

Состояние раскрытия запоминается. Окно меняет высоту вместе с содержимым
(`NSHostingView.sizingOptions = [.preferredContentSize]`).

### 3.3 Настроек нет (решение пользователя, 2026-08-26)

Отдельного окна настроек не существует. Всё управление — контекстное меню по правой кнопке:
«Обновить сейчас» (обновляет и лимиты, и состояние), «Запускать при входе», «Закрыть Claude
Limits».

**На поверхности панели нет ни одной кнопки** — это следствие аварии: кнопка закрытия,
проявлявшаяся при наведении, оказывалась под курсором во время перетаскивания окна, и
пользователь закрыл приложение, пытаясь его подвинуть.

### 4.1 Окно

Обычное `NSWindow` (подкласс, умеющий становиться ключевым), а не `NSPanel`: служебные панели
Mission Control не показывает. Заголовок прозрачный, пустой, без трёх кнопок — визуально окно
безрамочное, но для системы полноценное.

Уровень — на ступеньку выше обычных окон, **не** `.floating`: окна плавающего уровня Mission
Control не показывает, и перетащить их на соседний рабочий стол нельзя.

Привязка — `.managed`, то есть окно принадлежит одному рабочему столу. **«Виден на всех столах»
и «перетаскивается между столами» — взаимоисключающие режимы**; выбран второй (решение
пользователя 2026-08-26).

Три отказа, найденных при доведении до работы (2026-08-28), и их причины:

1. **Окно схлопывалось в 0×0.** Автоматический размер по содержимому
   (`sizingOptions = [.preferredContentSize]`, добавленный ради раскрытия блока
   состояния) конфликтовал с ручным `setContentSize(hosting.fittingSize)`, а тот на момент
   создания окна возвращает ноль. Приложение при этом запускалось, процесс жил, падений не
   было — снаружи это неотличимо от «программа не открывается». Теперь стартовый размер задан
   явно, ручная установка убрана, и через 1.5 с после запуска работает проверка: окно меньше
   40 пунктов по любой стороне — записать в журнал и вернуть размер.
2. **Панель уходила на чужой рабочий стол.** macOS запоминает, какому столу принадлежали окна
   приложения, и восстанавливает их там же. Пользователь запускал программу, а система молча
   уводила его на другой стол. Лечится показом через `.moveToActiveSpace` на один такт — и при
   запуске, и при повторном открытии.
3. **Окно уползало по экрану.** AppKit каскадирует окна с заголовком при каждом показе, и
   сдвинутое место сохранялось как «выбранное пользователем». Координаты теперь явно
   возвращаются после каждого показа; проверено тремя призывами подряд без смещения.

4. **Раскрытие блока состояния обрезало содержимое.** Размер окна не менялся: шапка с иконкой
   уходила за верхний край, инциденты — за нижний. Причина в способе измерения — `GeometryReader`
   сообщает размер, который окно ВЫДАЛО содержимому, а не тот, который содержимому нужен;
   зажатая вёрстка честно рапортовала свою же тесноту. Настоящий размер берётся у
   `NSHostingView.fittingSize`, а сигналом «пора мерить» служит preference-ключ. Корень вёрстки
   получил `fixedSize(vertical:)`, иначе SwiftUI молча ужимает содержимое вместо переполнения.
5. **Окно росло вверх.** Начало координат окна macOS — левый НИЖНИЙ угол, поэтому увеличение
   высоты поднимает верхний край. Теперь при изменении размера удерживается верхний край, и
   панель растёт вниз; в настройках хранится верхний левый угол, а не нижний (ключ переименован —
   сменив смысл значения, нельзя оставлять прежнее имя: старое значение прочиталось бы как своё
   и увело окно).
6. **Панель не приходила на текущий рабочий стол.** Мгновенное включение `.moveToActiveSpace` с
   немедленным сбросом не срабатывало — система не успевала отработать переезд. Режим сделан
   постоянным свойством окна: панель приходит к пользователю при активации приложения и при этом
   остаётся перетаскиваемой в Mission Control.

Два отказа сборочного скрипта, найденных в этом же заходе, — оба класса «инструмент солгал об
успехе»:

- **`--install` не останавливал работающую версию.** Новый бандл копировался в `/Applications`,
  но `open` на уже запущенном приложении лишь активирует СТАРЫЙ процесс. Две итерации подряд
  проверялись на неизменившемся коде. Установщик теперь останавливает работающую версию и
  подтверждает, что новая поднялась.
- **Шаг тестов глушил вывод через `2>/dev/null`.** Провал компиляции тестов остался немым, скрипт
  молча остановился на `set -e`, и снова проверялся старый бинарь. Вывод больше не глушится.

Общий вывод, стоящий отдельного слова: **«процесс жив» не означает «приложение работает».**
Проверка велась через `CGWindowListCopyWindowInfo` (размер, слой, присутствие на экране) и
снимок экрана — без этого окно нулевого размера на чужом рабочем столе считалось бы успехом.

Фон — плотный тёплый цвет, **не** матовое стекло: размытие «сквозь окно» рисует оконный сервер,
во время перетаскивания он его гасит, и панель выглядит серой до следующей перекомпоновки.
Надёжно вернуть эффект сразу после остановки окна не удалось (пробовали принудительное
пересоздание слоя), поэтому эффект убран целиком.

## 5. Модель данных

```swift
struct Limit { let percent: Int; let resetsAt: Date? }
struct Limits { let session: Limit?; let weeklyAll: Limit?; let weeklyFable: Limit? }
```

Разбор: идём по `limits[]`, отбираем по `kind`; для `weekly_scoped` дополнительно сверяем
`scope.model.display_name == "Fable"`. Неизвестные `kind` игнорируются молча. Отсутствующая
строка даёт `nil`, а не ноль: «нет данных» и «ноль процентов» — разные вещи и рисуются
по-разному.

## 6. Состояния и поведение при отказах

| Состояние | Причина | Панель |
|---|---|---|
| `ok` | ответ получен | три лимита, возраст данных |
| `stale` | отказ, кроме `401`/`403`/`429` | прежние значения серым + **названная причина** |
| `expired` | `401`/`403` | «Запусти Claude Code — он обновит токен» |
| `noCredentials` | нет `claudeAiOauth` или доступ не дан | «Нет доступа к токену Claude Code» |
| (без смены состояния) | `429` | ничего не меняется; на холодном старте — «жду очереди к серверу» |

Правила, обязательные к соблюдению:

1. **Причина отказа не выдумывается.** Ранняя версия называла «нет сети» любой отказ кроме
   `401` — и показывала это при живом интернете, когда на деле приходил `429`. Теперь каждый вид
   отказа имеет своё имя: `нет сети`, `сервер ответил N`, `ответ не разобран`, `сервер просит
   подождать`, `токен не принят`. Правило закреплено тестами.
2. **Утилита не запускает внешние программы** — ни браузер, ни `claude`, ни `open`. Ни при каких
   состояниях (раздел 2.5).
3. **Не обновляет токен сама.** Обновление ротирует refresh-токен и способно сломать рабочий
   вход в Claude Code. Отложено в раздел 11. Восстановление после `expired` происходит само:
   кэш с истёкшим сроком считается несвежим, связка перечитывается на следующем опросе.
4. **Последнее удачное значение не стирается** отказом.
5. **Чтение Keychain — вне главного потока.** `SecItemCopyMatching` блокируется на всё время
   показа системного диалога доступа; на главном потоке это вешало весь интерфейс до ввода
   пароля (ошибка допущена и исправлена 2026-08-27).
6. **Токен кэшируется в памяти до истечения срока.** Иначе обращение к Keychain шло на каждом
   опросе и система спрашивала доступ каждую минуту.

Опрос: лимиты и состояние — раз в 5 минут, плюс при пробуждении из сна, плюс по команде меню.
После отказа — пауза 5 минут; после `429` — пауза, названная сервером, иначе 90 секунд.

## 7. Уведомления

Пороги 80% и 95% по любому из трёх лимитов, по одному разу на окно (запоминается сработавший
порог и `resets_at`; при смене окна счётчик сбрасывается). Отдельно — «часовой лимит обнулился»
при переходе окна. Разрешение запрашивается один раз при первом запуске; отказ уважается молча.

## 8. Безопасность

- Токен **никогда** не покидает память процесса: ни файла, ни `UserDefaults`, ни лога. В журнал
  пишутся только вид отказа, код ответа и время.
- **Ноль сторонних зависимостей** — только системные фреймворки.
- Сеть: ровно два адреса по TLS — `api.anthropic.com` (с токеном) и `status.claude.com` (без
  токена). Ни телеметрии, ни аналитики, ни отчётов о сбоях наружу.
- Работа с Keychain — **только чтение**. Подпись ad-hoc локально.
- Журнал `~/Library/Logs/ClaudeLimits.log` обрезается до последних 200 строк.

## 9. Сборка и установка

`./make.sh` гоняет тесты, собирает релиз, укладывает бинарь в `Claude Limits.app` с `Info.plist`
(`LSUIElement = true` — без иконки в доке) и подписывает ad-hoc. Xcode не требуется.
`./make.sh --install` дополнительно кладёт в `/Applications` и запускает.

**Провал компиляции останавливает сборку.** В первой версии скрипта статус брался у `grep` в
конвейере, из-за чего ошибка компиляции проходила незамеченной и в бандл уезжал бинарь от
прошлой сборки — то есть можно было показать «работающее» приложение, собранное из старого кода.

Ad-hoc подпись меняется при каждой пересборке, поэтому macOS считает приложение новым и заново
спрашивает доступ к Keychain. Это ожидаемо при разработке и прекращается, когда пересборки
прекращаются.

Автозапуск — `SMAppService.mainApp.register()` по пункту контекстного меню.

## 10. Тесты

XCTest недоступен (раздел 2.6), поэтому тесты — отдельный исполняемый таргет `LimitsTests`,
запускаемый `swift run LimitsTests`, с ненулевым кодом возврата при провале. Сейчас **58
проверок**. Под тестами:

- разбор лимитов: полный ответ, без строки Fable, `weekly_scoped` чужой модели (не должен
  подменять Fable), незнакомый `kind`, `resets_at: null`, мусор вместо JSON;
- разбор записи Keychain, включая форму «только `mcpOAuth`» из раздела 2.5;
- пороги: срабатывание один раз на окно, сброс при смене окна, повторное срабатывание в новом;
- форматирование: время сброса, остаток, возраст данных (в том числе граница «только что»);
- **именование отказов**: `429`, `500`, ошибка разбора и таймаут не должны называться сбоем сети;
- разбор состояния сервисов: спокойный ответ и ответ со сбоем (инцидент, недоступный Claude
  Code, замедленный API, отброс групп-заголовков).

Фикстуры — реальные ответы эндпоинтов с вычищенными идентификаторами; «плохая погода» для
состояния сервисов написана вручную, поскольку вживую всё было исправно и эта ветка иначе
осталась бы непроверенной. UI тестами не покрывается.

## 11. Вне границ, с адресами

1. **Обновление токена своими силами** (refresh + запись обратно в keychain-item) — сняло бы
   состояние `expired` после долгого простоя Claude Code. Триггер: если на практике окажется,
   что это мешает. Требует отдельной проверки на риск рассинхрона с CC.
2. **Extra usage / кредиты** — данные уже приходят в том же ответе. Триггер: если пользователь
   начнёт ими пользоваться.
3. **История расхода** — накопление замеров и график. Триггер: вопрос «когда я обычно упираюсь».
4. **Поддержка иного размещения токена** — если Claude Code сменит формат хранения (раздел 2.5
   показывает, что такое случается). Триггер: первая же поломка чтения.
5. **Уведомления об инцидентах** — сейчас состояние сервисов только показывается. Триггер:
   первый пропущенный сбой.

## 12. Риски

| Риск | Вероятность | Что делаем |
|---|---|---|
| Claude Code меняет формат хранения токена | средняя (прецедент в 2.1.x) | типизированная ошибка и честное состояние, без попыток чинить |
| Эндпоинт меняет форму ответа | низкая | неизвестные `kind` игнорируются; отсутствующая строка даёт `nil`, а не падение |
| Ограничение частоты ужесточат | средняя | `429` уже не считается ошибкой; интервал легко поднять |
| Пользователь не дал доступ к Keychain | высокая при первом запуске | состояние `noCredentials`; повторный запрос — по команде меню, не автоматически |
| Fable-лимит отсутствует у аккаунта | известная | строка просто не рисуется |
